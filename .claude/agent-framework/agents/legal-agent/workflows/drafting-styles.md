# Drafting Styles by Output Type

A solicitor writes a board memo, a witness statement, and a without-prejudice letter in
three different registers. This agent should too. Pick the matching style; don't default
everything to the same generic prose.

| Output type | Register | Notes |
|---|---|---|
| Internal memo | Plain, structured, headed sections | Facts → issues → analysis → recommendation. Internal audience, can name uncertainty freely. |
| Board / General Counsel advice note | Executive-first | Bottom line up front, then supporting analysis. Assumes a non-lawyer reader; avoid unexplained jargon. |
| Counsel instructions | Narrow, factual, no editorializing | See `counsel-handoff.md` — the brief format, not a draft opinion. |
| Without-prejudice letter | Formal, hedged, no admissions | **Draft only, never sent by this agent** (`scope-boundaries.md`). Mark "WITHOUT PREJUDICE" at the top; avoid any language that could be read as an admission of liability. |
| Letter before claim / letter before action | Formal, cites the specific breach and remedy sought | Follow Practice Direction – Pre-Action Conduct structure; draft only, name the human sender. |
| Contract clause | Precise, defined terms used consistently, no ambiguity | Flag any drafted clause as a starting point for counsel review, not a final version. |
| Regulatory response | Formal, responsive point-by-point to the notice | Address every numbered point in the regulator's notice; do not volunteer information beyond what's asked; draft only. |
| Witness statement draft | First person, chronological, facts only — no legal argument | Never draft opinion or characterization into a witness statement; that's for the witness's own words, reviewed by counsel. |
| Case summary | Neutral, both sides' positions represented | Facts, procedural history, issues, current status — not an advocacy piece. |
| Risk note | Structured per `templates/risk-register.md` | Likelihood × severity × mitigation, not prose paragraphs. |
| Executive summary | 3–5 sentences, no citations inline | Full citations live in the body; the summary is for someone who will only read the summary. |
| Decision record | See `decision-record-protocol.md` | The one style with its own dedicated module — don't duplicate its structure here. |

## Shared rules across every style

- The disclaimer from `scope-boundaries.md` appears on every substantive artifact,
  regardless of register.
- Every citation follows `research/citation-verification.md` regardless of how informal the
  document's tone is.
- Anything addressed to a third party (regulator, opposing party, ToS-holder) is drafted
  and stopped — never sent by this agent.
