# Task Generator

> Architecture Agent — AI-DLC Task Coordination

---

## Purpose

After producing a design, the Architecture Agent creates a structured task list
for every downstream agent. This makes the Architecture Agent the strategic
coordinator for the AI-DLC pipeline — not just a designer.

---

## Task Generation Flow

```
Architecture Design Complete
    ↓
Generate Agent Task Packages:
    ├── Java Agent Tasks
    ├── React Agent Tasks
    ├── Test Agent Tasks
    ├── DevOps Agent Tasks
    └── Security Review Tasks
```

Each task package includes:
- Agent name
- Task description
- Input artifacts (what to use)
- Output artifacts (what to produce)
- Standards to apply
- Acceptance criteria
- Dependencies on other tasks

## ILR Example: Document Upload Feature

```markdown
## Agent Task Package: Document Upload and AI Processing
## Generated by: Architecture Agent
## ADRs: ADR-001 (Event-Driven), ADR-002 (PostgreSQL), ADR-003 (Bedrock)

### Java Agent Tasks

#### JA-01: Document Service — Upload Endpoint
- POST /api/v1/documents (multipart)
- Generate S3 presigned URL, store metadata
- Publish: document.uploaded event
- Standards: java/*, spring-boot/*, spring-boot/events.md

#### JA-02: Document Service — Status Endpoint
- GET /api/v1/documents/{id}
- Return DocumentResponse with processing status
- Standards: spring-boot/rest-api.md

#### JA-03: AI Orchestrator — Pipeline Implementation
- Subscribe to document.uploaded via SQS
- Execute pipeline stages (see ai-pipeline-designer.md)
- Publish stage completion events
- Standards: spring-boot/events.md, spring-boot/resilience.md

#### JA-04: Database Migrations
- V1__create_documents_table.sql
- V2__create_processing_jobs_table.sql

### React Agent Tasks

#### RA-01: Document Upload Component
- Drag-and-drop upload area
- Progress indicator
- WCAG AA accessible
- React Query for status polling

#### RA-02: Document Status Display
- Show processing stages (OCR → Classification → Extraction)
- Confidence-based UI (auto-accepted vs awaiting confirmation)
- Action prompts for CONFIRM_REQUIRED stage

### Test Agent Tasks

#### TA-01: Document Service Unit Specs (Spock)
- DocumentServiceSpec (upload, status, validation)
- DocumentPipelineOrchestratorSpec (pipeline stages)

#### TA-02: Document API BDD Integration Specs (Spock)
- "should upload document and return 201"
- "should return processing status"
- "should return 400 for invalid file type"
- "should reject files over 10MB"

#### TA-03: React Component Tests
- DocumentUpload component test
- DocumentStatus display test

### DevOps Agent Tasks

#### DA-01: Helm chart updates
- document-service: new ConfigMap values for S3 bucket
- ai-orchestrator: SQS queue environment variables

#### DA-02: CI/CD updates
- Build and scan ai-orchestrator image
- Staging deploy + smoke test for new endpoints

### Security Review Tasks

#### SR-01: Document Upload Security
- Verify file type validation (not just extension)
- Confirm S3 bucket policy (private + signed URLs only)
- Confirm audit log on every upload
- Check PII in document metadata is encrypted
```

## Checklist

- [ ] Task package generated for every feature design
- [ ] Every agent has explicit tasks with acceptance criteria
- [ ] Task dependencies documented (parallel vs sequential)
- [ ] Input artifacts linked (API contract, ADRs, data model)
- [ ] Standards referenced per task
- [ ] Security review tasks always included
- [ ] Task package reviewed before any agent starts work
